# 代码审查清单（主 agent 用）

本清单由主 agent 在每单的 PR 上逐条执行，结果用中文汇报给人。目的是把"看起来没问题"变成"逐条可核对"。

## A. 夹带检查（先做，最快出结论）

- [ ] `git diff --stat` 的文件数与 issue 范围相称
- [ ] 没有触碰：`docker/`、`compose.yml`、`storage/`、`.github/workflows/`、`*/db/migration/`、密钥与凭据文件、`.scratch/`
- [ ] 没有依赖变更（`package.json` / `pom.xml` / lockfile）
- [ ] 没有全文件格式重排（diff 里不出现大片与需求无关的空白/引号变更）
- [ ] 没有删除或 `skip` 既有测试
- [ ] commit 消息与 PR 描述和实际 diff 一致

## B. 复述测试（自明性）

不看代码先问自己一句：

> 数据从哪来 → 做了什么 → 为什么这么判 → 输出到哪

- [ ] 能用一句话复述主线
- [ ] 复述不出来 → 打回，理由写"主线不清：<具体文件:行>"

## C. 反过度工程（对照 `AGENTS.md` 第 1~8 条）

- [ ] 没有对类型系统已排除的情况做运行时判空（第 2 条）
- [ ] 没有新增 `try/catch` 却没说明捕获什么、之后做了什么不同的事（第 5 条）
- [ ] 新增抽象层时，PR 里能指出 ≥2 个现存调用点；指不出 → 打回（第 3 条）
- [ ] 没有为"将来可能需要"预留参数、配置项、抽象层（第 4 条）
- [ ] 注释写的是 why 而非 what（第 6 条）
- [ ] 嵌套不超过 3 层，早返回优先（第 7 条）

## D. 复用检查（对应 `front/AGENTS.md` 积木清单）

- [ ] 新增的 util / 组件在 `front/src/lib` 与 `front/src/components/community` 里没有同类实现
- [ ] PR 描述里有"为什么不用 <候选>"一句（或用 `已有实现：无` 说明已查过）

## E. 证据核对（它说 vs 实际）

- [ ] 重跑 PR 描述里声称跑过的命令：`npm run lint` / `npx tsc --noEmit` / `npm run test` / `npm run build`
- [ ] PR 描述的"验了什么"与实际输出一致
- [ ] 新增行为有对应测试；修 bug 有能复现该 bug 的测试

## F. 审查强度分级

| 改动类型 | 强度 | 怎么审 |
|---|---|---|
| 业务页面 / 业务接口 | 弱 | 只看意图与夹带；实现细节放行 |
| 公共 util / 组件库 | **强** | 逐行看实现，对照 C、D |
| 中间件 / 配置 / 构建 | **强** | 逐行看 + 本地实际跑起来 |
| 脚手架 / 工具脚本 | 中 | 看用法与失败路径 |

## 汇报模板

```
范围：<N 文件 +A/-D 行>，与 issue 相称 ✅/❌
夹带：无 / <具体>
复述：<一句话主线>
过度工程：无 / <文件:行 违反第 N 条>
复用：无重复 / <与 xxx 重复>
证据：lint ✅ tsc ✅ test ✅(39) build ✅ — 我本地重跑一致
结论：可合并 / 打回（理由：…）
```
