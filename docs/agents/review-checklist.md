# PR 审查清单

Worker 自审与 TUI 主 agent 独立审查共用本清单。先读取 Issue、关联规格、完整 diff 和涉及目录的 AGENTS.md；沿改动路径查看调用方和测试，再给结论。

## 所有改动

- 逐项核对验收标准，标明实现、证据或未完成项；PR 描述与实际改动一致。
- 检查是否夹带无关重构、依赖升级或格式重排；依赖、部署、迁移变更核对明确授权及验证，不因文件名自动否决。
- 对行为变更检查成功路径、失败路径和受影响调用方；审查测试断言是否真的证明行为。测试删除或 skip 必须有依据。
- 对照根 AGENTS.md「实现与审查共用准则」，检查复用候选、输入契约、防御分支、异常语义、抽象用途与主路径。报告具体位置和依据，不能仅以“AI 味”或个人偏好要求返工。
- 读完代码能描述输入 → 主要处理 → 输出及关键失败。主线不清时指出造成跳转或歧义的具体位置，不要求每个复杂算法都压成一句话。

## 按风险增加检查

| 风险 | 增加的审查 |
|---|---|
| 文档、静态文案 | 核对准确性、链接和实际效果 |
| 普通业务行为 | 核对状态变化、错误语义、调用契约和回归用例 |
| 鉴权、权限、支付、隐私、数据写入、事务、并发 | 逐路径检查越权、部分失败、重复请求及一致性；需要相应测试证据 |
| 公共能力、依赖、迁移、部署 | 检查调用方、兼容性、运行前提与恢复办法；必要时实际启动或集成验证 |

命中多类时采用较高要求。业务代码也可能高风险；小 diff 不代表低风险。

## 验证与合并

验证范围以 `issue-tracker.md` 为准。检查 CI 真实运行的任务及其提交 SHA，区分成功、未触发、跳过与失败。相同 SHA、可信环境的充分证据可复用；存在报告矛盾、覆盖缺口、环境差异或 main 更新时重跑相关检查，避免每单无条件重复全部构建。

界面变化核对预览操作与截图；API/缺陷核对请求或复现步骤。未运行的场景写明，不用静态 diff 推断“效果已验证”。

技术结论与产品验收分开：主 agent 报告技术依据，维护者确认产品取舍，或在事先授权的判据内委派判断。Approve/review 与 merge 是不同动作；只有明确授权才执行合并。

## 汇报

- 结果：本单改变了什么，验收项哪些满足。
- 发现：`文件:行`、问题、依据和影响；没有问题也说明审查范围。
- 证据：提交 SHA、实际检查结果、复用证据及未验证项。
- 人工验收：预览/操作路径、需要确认的取舍。
- 建议：可合并 / 需修改 / 需补证据；合并授权状态。
