# 鸣潮社区 UI 规范

## 1. 视觉方向

页面采用“深色导航 + 冷灰背景 + 青绿色操作色”的鸣潮社区方向。布局参考库街区的信息层级：顶部是全局导航，桌面端左侧是频道，中间是主要内容，右侧是推荐、资讯和工具；不复制官方 Logo、角色立绘、二维码或页面代码。

## 2. 设计 Token

| 用途 | 值 |
| --- | --- |
| 顶部导航 | `#17191b` |
| 页面背景 | `#f3f5f8` |
| 卡片背景 | `#ffffff` |
| 主文字 | `#263442` |
| 次级文字 | `#8996a5` |
| 鸣潮青 | `#14cbd3` |
| 青色浅底 | `#e7fafb` |
| 分割线 | `#e8edf2` |

正文使用系统无衬线字体；标题和正文保持较舒适的中文行高。圆角以 8px 为主，按钮避免过大的胶囊形，信息卡片优先使用轻边界和留白表达层级。

## 3. 布局

- 桌面端：顶部导航固定在页面顶部；内容区域采用左侧频道、中间主栏、右侧信息栏三栏网格。
- 帖子详情：左侧互动栏可随内容滚动，右侧作者与分区栏使用 `position: sticky` 固定在视口内。
- 移动端：内容变为单列；频道和搜索收进抽屉/操作按钮；右侧信息栏移到内容后方或隐藏。
- 主要内容最大宽度约 1320px，避免大屏内容过度拉伸。

## 4. 组件状态

- 加载中：显示与内容区域同宽的轻量状态块，不使用阻塞式全屏 Loading。
- 空数据：说明当前没有内容，并提供返回推荐或调整筛选的操作。
- 请求失败：保留可用的本地/缓存内容，同时明确提示“后端暂不可用”，不可静默伪装成实时数据。
- 写入中：提交按钮禁用并显示进行中状态，避免重复提交。
- 未登录：触发统一登录弹窗，登录成功后继续执行原操作。
- 成功/失败：使用短时 Toast；表单失败保留用户已输入内容。

## 5. 交互与可访问性

按钮必须使用真实 `button` 或 `Link`，菜单提供 `aria-expanded`/`role=menu`，表单字段有可见标签或 `aria-label`。新标签页打开帖子时使用 `target="_blank"` 并配合 `rel="noopener noreferrer"`。桌面和 390px 移动视口都不得产生意外横向滚动。
