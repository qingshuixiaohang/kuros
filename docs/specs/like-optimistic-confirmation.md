# 点赞操作前端确认边界（#189）

前端对用户和帖子保存独立操作，使用操作 ID 和目标状态发起写入。受理后保留乐观显示，通过操作查询获得 MySQL 结果；明确未受理才回滚。未知投递会以相同操作 ID 重试，有限退避后仍未知则保持待确认，并在页面交互或重新进入时继续查询。记录保存在浏览器本地，无法保存时不发送新操作。

当前按后端开发工作区的 `POST /api/v1/interaction-operations`（`operationId`、`postId`、`type: LIKE | UNLIKE`）及 `GET /api/v1/interaction-operations/{operationId}`（`UNKNOWN`、`APPLIED`，后者带 `state`）实现。后端尚在实施中，集成时需核对端点、错误码和终态；当前代码没有可用的 `FAILED` 查询终态。

普通读取没有可比较版本，因此取消在途查询并保留操作查询结果覆盖普通读取，避免迟到请求和 Redis 陈旧回填撤销已确认结果。后续交互与页面恢复时重新查询该操作，获取当前 MySQL 状态；但两次确认之间无法及时反映其他用户计数变化，也无法提供严格单调或实时计数。跨设备、跨浏览器和其他标签页的并发操作不在本地状态隔离范围内，仍依赖后端顺序与幂等保障。
