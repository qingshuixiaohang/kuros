# 单体项目生产化与 Docker Compose 部署基线

## 状态

- 阶段：implement + TDD 已完成，进入 code-review
- 目标：在不引入 Redis、消息队列或微服务的前提下，让当前 Spring Boot + Next.js 单体 MVP 可以被稳定、可重复地启动
- 部署优先级：Windows 本地 Docker Compose；为后续云服务器部署保留环境变量和数据卷边界

## 背景

当前项目已经完成社区 MVP，但启动依赖 MySQL、本地 Java/Maven 和 Node.js 环境。数据库连接、图片目录、跨域和前端 API 地址主要依靠本机配置，无法通过一个统一命令复现完整环境。

本阶段只解决“单体应用可配置、可检查、可容器化运行”问题，不提前引入中间件或拆分服务。

## 已确认决策

1. 后端继续保持单个 Spring Boot 应用，前端继续保持独立的 Next.js 应用。
2. MySQL 通过 Docker Compose 管理，并使用命名数据卷持久化数据库数据。
3. 后端上传文件目录映射为宿主机数据卷，应用重启后图片不丢失。
4. Flyway 继续作为唯一数据库结构变更入口，禁止通过 `ddl-auto=update` 修改表结构。
5. 登录继续使用现有 Cookie 会话；本阶段不改成 JWT，也不引入 Redis 会话。
6. 开发验证码继续使用显式开发配置；生产环境必须关闭验证码回显并通过环境变量注入密钥/凭据。
7. 前端 API 地址、后端数据库、CORS、Cookie Secure 和存储目录全部通过环境变量配置。
8. 通过 Spring Boot Actuator 提供健康检查；健康检查只反映服务和数据库是否可用，不暴露敏感配置。

## 目标范围

### 后端

- 增加可用于容器运行的 Dockerfile。
- 增加生产配置模板，不提交真实密码、密钥或开发验证码。
- 增加 `/actuator/health` 健康检查能力。
- 明确数据库连接、Flyway、CORS、会话 Cookie、图片目录的环境变量。
- 应用启动时在数据库不可用时快速失败，并输出可定位的配置错误。

### 前端

- 增加 Dockerfile 和容器启动说明。
- 统一前端服务端/客户端使用的后端 API 基地址配置。
- 增加 `.env.example`，说明本地开发和容器运行所需变量。
- 保持现有页面路由、登录、评论、互动和发布行为不变。

### Docker Compose

- 提供 MySQL、Spring Boot 后端、Next.js 前端三个服务。
- MySQL 使用命名卷保存数据。
- 后端存储目录使用宿主机或命名卷保存上传图片。
- 后端等待 MySQL 健康后再启动。
- 前端通过环境变量访问后端，不在代码中写死容器地址。
- 提供停止、重启和查看日志的常用命令。

### 文档

- 更新 README，提供本地原生启动和 Docker Compose 启动两种方式。
- 说明首次启动、数据库迁移、默认开发验证码、图片目录和常见故障。
- 明确当前方案是开发/演示部署基线，不等同于公网生产安全方案。

## 非目标

- 不引入 Redis、RocketMQ、MinIO、Elasticsearch、Nacos、Gateway 或微服务拆分。
- 不修改现有 REST API、数据库业务表和前端业务功能。
- 不实现真实短信、对象存储、域名 HTTPS、云服务器部署或自动发布流水线。
- 不在 Docker Compose 中加入管理员初始化、测试数据重置等破坏性命令。

## 验收标准

1. 在一台没有本地 MySQL、Java 和 Node.js 运行时的机器上，安装 Docker 后可以按 README 启动完整应用。
2. MySQL、后端、前端三个容器均能启动；后端健康检查在数据库就绪后为 `UP`。
3. 浏览器可以访问首页、登录、帖子详情、评论和发布页面。
4. 通过页面发布的评论、帖子和图片在容器重启后仍符合预期：数据库数据和上传图片不丢失。
5. 修改 API 地址、数据库密码、CORS 来源和存储目录时只需修改环境变量，不需要改代码。
6. `docker compose config` 通过，且不包含真实凭据。
7. 原生开发命令、后端测试、前端 lint/build 和已有 Playwright 回归不回退。
8. 前端和后端容器日志能够定位数据库连接失败、迁移失败和 API 地址配置错误。

## 测试接缝

- 配置接缝：环境变量覆盖默认值，敏感变量不出现在版本库。
- 数据接缝：MySQL 数据卷和上传文件卷在重启后保持数据。
- 服务接缝：后端健康检查必须等待数据库就绪，前端必须能访问后端 API。
- 回归接缝：现有登录、帖子、评论、互动、发布和图片上传流程继续可用。
- 运维接缝：README 命令与 Compose 服务名、端口、卷名保持一致。
