# 浏览器登录使用安全 Cookie 会话

鸣潮社区的前后端分离网页采用安全 Cookie 保存登录会话，不让前端直接持久化敏感令牌。相比把令牌交给浏览器脚本管理，这个方案更适合当前网页端登录弹窗和后续的登录态恢复；代价是前后端请求必须明确处理凭据、跨域和 CSRF 防护。

## 考虑过的方案

- **前端保存 JWT**：实现直观，但敏感令牌暴露给浏览器脚本后，前端安全边界更复杂，暂不采用。

## 影响

- 登录、获取当前用户和退出登录需要围绕会话设计统一接口。
- 前端请求跨域时必须显式携带凭据，后端也必须限制允许的来源。
- 写操作需要配套 CSRF 防护策略，不能只依赖登录态。
