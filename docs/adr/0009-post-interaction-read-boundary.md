# 0009. 帖子详情通过端口读取实时互动计数

日期：2026-10-20

状态：已接受

## 背景

`CommunityPostService` 直接依赖互动模块的 `InteractionRedisStore`、`InteractionKind`，而互动服务与投影又依赖帖子实体和仓储，形成 `post` 与 `interaction` 包之间的双向依赖。详情读取对 Redis 实时计数的依赖是有意的，但不应让帖子应用服务了解互动存储实现。

ADR-0006 的详情读取约束继续有效：详情缓存只保存帖子内容字段；每次组装详情响应时读取 Redis 实时点赞/收藏计数；Redis 计数键缺失时才惰性读取帖子的数据库冗余计数作为基线。

## 决策

1. 由帖子域定义一个小型实时互动计数读取端口；互动域提供实现。帖子应用服务只依赖帖子域端口，不再导入互动包。
2. 端口只负责读取点赞数和收藏数，并接受惰性基线供给器。Redis 命中时不得执行基线查询；Redis 未命中时使用数据库冗余列作为基线并按现有规则回填。
3. 本切片只调整帖子详情的计数读取边界。互动写接口、当前用户 liked/favorited 状态、帖子可见性校验、消息投影、对外 DTO/API 和一致性语义保持不变。
4. 继续遵守 ADR-0006：计数不进入 `PostDetailContent` 或两级详情缓存。
5. 不增加数据库迁移、Redis key 或网络调用。

## 备选方案

- **把 `InteractionRedisStore` 移到 shared**：拒绝。它是互动域的 Redis 持久化细节，放入 shared 会扩大公共层并掩盖领域所有权。
- **让帖子域直接读取关系表计数**：拒绝。会绕过 Redis 实时源并改变异步投影下的可见性。
- **把完整互动状态 API 搬进帖子域**：拒绝。本切片只需要详情计数读取，不应扩大帖子域职责或改变 liked/favorited 行为。

## 验证

- 单元测试验证 Redis 命中时使用实时值且不调用基线供给器；Redis 未命中时调用对应数据库基线。
- 帖子详情集成测试验证响应计数语义保持，且缓存内容仍不包含互动计数。
- 源码依赖检查确认 `post` 主代码不再导入 `interaction` 包，`interaction` 仍可依赖帖子域的实体/仓储。
- 运行后端编译和受影响的定向测试。
