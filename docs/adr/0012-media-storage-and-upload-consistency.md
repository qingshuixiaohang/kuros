# 0012. 通过存储策略保存图片，先登记媒体资产再写文件

状态：已接受（依据存储策略与上传一致性切片补录）

## 背景

帖子需要引用图片。单机可以把文件放在本地存储卷，多实例则需要让各实例读到同一份文件。上传横跨 MySQL 和文件存储，原来先写文件时，如果保存元数据失败或进程退出，临时资产清理任务找不到这个文件。

## 决策

例子：你先上传一张攻略截图，还没点「发布」就关掉编辑器。MySQL 已有这张图的临时资产记录，清理任务以后能按存储键找到并删除过期文件。如果回到编辑器成功发布，帖子会关联这张图，资产转为已关联状态。

- 内容服务用 `StorageStrategy` 切换本地磁盘或 MinIO，默认本地。文件存储保存图片内容，MySQL 的媒体资产记录保存所有权、存储键和生命周期。上传返回媒体资产标识与 URL，帖子通过媒体资产建立关联。切换存储方式需要单独迁移已有对象。
- 上传时先提交临时资产记录，再调用所选策略写文件。上传方法挂起调用方事务，让仓储事务在写文件前提交。元数据写失败时立即结束上传。
- 如果文件写入报错，尝试删除同一存储键。删除成功后把记录标记为已删除，清理未完成时保留临时记录供定时任务继续处理。调用方收到原始上传错误。成功上传的临时图片在关联帖子后成为已关联资产。

## 备选与代价

始终用本地磁盘最容易部署，但不同实例默认看不到彼此的文件。始终用 MinIO 会增加单机依赖。先写文件再尝试删除可以处理部分报错，但进程在元数据登记前退出时，仍需要扫描存储才能找回孤儿对象。先登记允许留下待清理的临时记录，因而依赖后续清理；历史上已缺少元数据的孤儿对象需要单独盘点。
