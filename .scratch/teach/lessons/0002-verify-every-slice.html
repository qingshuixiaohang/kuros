0.2 接口测试的三种姿势（不装任何东西就能开始）

姿势怎么用适合
Swagger UI开 localhost:8090/swagger-ui/index.html → 展开任意 GET 接口 → Try it out → Execute。全部接口定义来自代码自动生成（切片 #6）读接口直接调；写接口会 401（Swagger 里没有登录态，属预期）

浏览器 F12 Network操作页面 → Network 里右键任意请求 → Copy as fetch / Copy as cURL → 改参数重放复现"刚才那个请求"最快
为什么没有 JMeter？按路线图（CONTEXT.md 2026-09-21 方向纠偏），Jmeter 压测排在切片 #15+ 还没立项。原因：项目纪律"禁止无压测依据的并发表述"——压测数据必须真实采集，所以要专门立一个切片：写压测计划 → 跑出 P95/吞吐数据 → 写进复盘。现在手头工具（Swagger/Apifox/F12）覆盖"功能验证"；等你 ready 说一声，#15 就从 JMeter 压测 + Sentinel 触发实验开始立项。

切片 #1 · 分布式会话 + RBAC（登录）

【是什么】手机号+验证码登录（首次登录自动注册），会话存 Redis，管理员有专属权限。

【操作】① 首页随便点一个 ♡ → 弹"欢迎登录"框。② 手机号输入 13800000002 → 点"获取验证码"→ 出现 toast"开发验证码已填入：123456"且输入框自动填好。③ 勾选用户协议 → 点"登录" → toast"已登录鸣潮社区"，右上角出现昵称"无音区夜行者"。④ 退出登录 → 换 13800000001 登录 → 地址栏进 /admin/reports。

【亲眼确认】F12 → Application → Cookies → KUROS_SESSION（HttpOnly，JS 读不到——这就是安全点）；Network 里 POST /api/v1/auth/code、POST /api/v1/auth/login（响应 Set-Cookie）、GET /api/v1/auth/me 返回 {"nickname":"无音区夜行者","role":"USER"}；ADMIN 进审核台正常、USER 进同页被拒（403）——RBAC 生效。

【看哪】user 服务 IDEA 控制台（验证码签发、登录日志）；观测点⑤ keys 'satoken*'——会话键在 Redis 里，所以重启 user 服务你也不掉线；Redis GUI 里能看到键的 TTL（30 天）。

【翻车对照】验证码没自动填 → APP_AUTH_DEV_CODE_EXPOSED 没开；登录报"验证码无效" → 超过 5 分钟过期或输错；整页打不开 → gateway 没起（所有请求都走 8080）。

切片 #2 · 存储策略模式（图片上传）

【是什么】图片字节存"仓库"（本地目录或 MinIO），MySQL 只存档案卡（media_assets 表），策略可切换。

【操作】① 开 /publish?type=guide → 标题"素材测试帖"、随便写正文 → 点图片上传区选 1~2 张小图（可拖拽排序）→ 点发布。② 跳转详情页，图片正常显示。

【亲眼确认】Network 里 POST /api/v1/files/images 返回 2xx（实测 201 Created，因为新建了文件），响应体带 http://localhost:8080/media/xxxx.png；文件管理器打开后端"工作目录 + storage"下的文件夹——IDEA 启动时工作目录是项目根，即 G:\kuros-web\storage\（若从 kuros-backend 目录命令行启动则是 kuros-backend\storage\）——图片变成 UUID 名躺在里面；Navicat 执行 SELECT * FROM kuros.media_assets ORDER BY created_at DESC; 最顶上多一行（storage_key、content_type、size_bytes、owner_id）。

【看哪】storage 目录 + media_assets 表（这就是"仓库+档案卡"的证据）；MinIO 9001 默认为空——因为默认 local 模式不经过它。

【进阶实验】.env 里加 APP_STORAGE_TYPE=minio → 重启 backend（IDEA 重跑）→ 再传图 → MinIO 9001 的 kuros-media 桶出现同样文件——业务代码零改动，换的只是策略实现。

【翻车对照】上传 413/报错且图大于 1MB → Spring 默认 multipart 上限 1MB（已知待修项）；401 → 没登录；图片 404 → 后端重启后 storage 目录变了（本地模式文件在工作目录里）。

切片 #3 · 两级缓存（Caffeine L1 + Redis L2）

【操作】进任意帖子详情 → 返回列表 → 再进同一个帖子 → 等 60 秒后再进一次。

【亲眼确认】观测点⑤出现 cache:postDetail:<postId>（这是 L2，TTL 60 秒）；第二次进详情明显更快（L1 Caffeine 在进程内存里，纳秒级）；60 秒后键消失，再访问时重建——TTL 到期的工作方式肉眼可见。注意：点赞数不在这个键里（详情只缓存内容字段，计数永远实时读 Redis——防止缓存和计数打架，#13 的架构决策）。

【看哪】观测点⑤；backend 控制台（缓存重建/广播失效日志）。

【翻车对照】键一直不出现 → 看后端控制台有无 Redis 连接错误；改了帖子标题但详情没变 → 缓存未失效就该变了（有 afterCommit 失效逻辑，如果真出现请截图给我——那是个 bug）。

切片 #4 · Sentinel 限流

【是什么】帖子列表接口 100 QPS 阈值，超了返回 429。手点不可能触发（阈值刻意放大避免误伤演示）。

【现在能看的】⑨ 号观测点 :8090/actuator/metrics 页面 Ctrl+F 搜 sentinel；backend IDEA 控制台确认 SentinelRateLimitInterceptor 装配日志（启动时）。真正的触发实验需要 JMeter 压测——#15 立项后补上，到时能看到 429 和限流指标曲线。

切片 #5 · Redis 分布式锁（并发防护）

【操作】02 号登录 → 开 /users/10000000-0000-0000-0000-000000000001（01 号主页）→ 快速连点"关注"按钮 5~10 次。

【亲眼确认】Navicat：SELECT * FROM kuros_user.user_follows; ——不管点多快，follower=02 & following=01 永远只有一行，全程无 500。锁的存在让并发请求排队+幂等检查兜底。

【看哪】user 服务 IDEA 控制台（锁获取/释放日志）；Redis GUI 里 lock* 键——存在窗口极短（毫秒级），手速快能撞见。

【翻车对照】出现两行重复关系 → 截图给我，那是严重 bug（历史上修过"锁-事务竞态"，见 HANDOFF 陷阱 7）；点关注 401 → 没登录。

切片 #6 · OpenAPI 文档

【操作】开 localhost:8090/swagger-ui/index.html → 按 tag 分组浏览 → 展开 GET /api/v1/posts → Try it out → page=1 pageSize=5 → Execute。

【亲眼确认】200 响应体是完整 JSON（data + meta 分页信息）；每个接口的参数说明都来自代码注解。

切片 #7 · Actuator + Micrometer

【操作】依次开 :8090/actuator/health（各组件健康明细）、:8090/actuator/metrics（指标清单，点进任意一个看数值）、:8090/actuator/prometheus（Prometheus 抓取格式——找 jvm_memory_used_bytes、http_server_requests_seconds_count）。

【亲眼确认】health 里 mysql/redis/diskspace 各自 UP；prometheus 文本里能搜到你刚才发请求产生的计数增长——这就是"可观测性"的原料。

切片 #8 · Nacos 注册与配置

【操作】8081 → 服务管理 → 服务列表 → 逐个点开 kuros-backend / kuros-user / kuros-gateway。配置管理 → 配置列表 → kuros-backend.properties。

【亲眼确认】三个服务的健康实例数=1（你只起了一个 JVM），点开能看 IP+端口（本机局域网 IP）；这就是 gateway 能"找到"另外两个服务的原因——没有 Nacos，网关就是个瞎子。

切片 #9 · Gateway 统一入口

【亲眼确认】② 号观测点：前端发任何请求，域名全部是 localhost:8080。路由实验：浏览器直接开 localhost:8090/api/v1/auth/me → 404（auth 在 user 服务上，直连 backend 当然没有）→ 同样请求走 localhost:8080/api/v1/auth/me → 401（网关把它转给了 user，user 说你没登录）。404 vs 401 的差别就是网关路由存在的证明。

切片 #10 · 服务拆分（跨服务组合与降级）

【亲眼确认】详情页作者昵称"无音区夜行者"只存在于 kuros_user 库（Navicat 看 kuros_user.users）——backend 的 kuros 库里没有 users 表，昵称是 backend 通过 Feign 实时拉回来填的。

【降级实验（本课最精彩）】IDEA 停掉 user 服务 → 刷新帖子列表 → 作者显示占位"用户"，页面不报错 → IDEA 重启 user → 刷新 → 真实昵称恢复。这就是"组合视图降级不 500"：强依赖（登录）挂了才 503，弱依赖（昵称回填）挂了优雅占位。

【看哪】backend 控制台在 user 停机瞬间会刷 Feign 调用异常（连接拒绝），随后是降级逻辑日志。

切片 #11 · 互动异步化（RocketMQ）

【操作】登录后对任意帖子点赞。立刻做两件事：看数字、开 8082。

【亲眼确认】① 点赞数字瞬间 +1——这个数来自 Redis 前置计数，不是数据库（互动写路径：Redis 计数 → RocketMQ 消息 → 消费者异步落库）。② 8082 → 消息 → Topic 列表 → post-interaction-topic → 消息量 +1 → 点"消息轨迹"看到被 interaction-consumer-group 成功消费。

【看哪】backend IDEA 控制台消费日志；观测点⑤ keys 'interaction:*'（count 键 + 用户状态键）。

【翻车对照】点赞 500 → 罕见（MQ 挂了会同步降级直写数据库）；数字加了但 Topic 没消息 → 看 backend 控制台 MQ 发送失败降级日志。

切片 #12 · Feed 流（ZSet Timeline）

【操作】02 号关注 01 号 → 退出换 01 登录 → 发一帖 → 换回 02 → 首页点"关注" tab。

【亲眼确认】01 刚发的帖子出现在 02 的关注流里——发帖瞬间 backend 把帖子 ID 推进每个粉丝的时间线（Push-on-publish，Feign 拉粉丝列表→Redis Pipeline 批量写）。观测点⑤ keys 'feed:timeline:*'——01 号一个键，ZSet 结构，score 是发布时间戳，容量 500、30 天过期。

【翻车对照】关注 tab 空 → 没关注任何人或对方没发过帖（时间线只存关注后产生的推文）。

切片 #13 · 读路径加固（游标分页）

【亲眼确认】首页往下滚触发"加载更多"→ ② 号观测点看请求：GET /api/v1/posts?limit=10&cursor=eyJzb3J0S2V5Ijo...（base64 不透明串）——不是 page=2。响应 meta 里带 nextCursor，下一页请求透传它。深翻第 1000 页和第 2 页耗时相同（这就是游标分页的存在意义）；代价：不能跳页、没有总条数——所以界面上没有页码按钮。

【对照实验】Swagger 里调 GET /api/v1/posts?page=2&pageSize=10（不传 limit）→ 走旧 offset 模式也通——双契约并存，cursor 是给前端的，offset 是兼容保留。

切片 #14 · 全文检索 + CDC（四站接力，最精彩）

【操作】发一篇标题带独特词的帖子（"汐语测试甲乙丙"），同时按下秒表，然后逐站观察：

站去哪看到什么
① canaldocker compose logs -f canal-server捕获 posts 表 binlog 变更的日志滚动
② MQ8082 → Topic kuros-post-cdc消息量 +1（canal 投递）
③ backendIDEA 控制台PostCdcHandler 消费日志：拿 postId → 回源查库组装 → 写 ES
④ EScurl localhost:9200/_cat/indices?vpost_search 索引 docs 数 +1；再 curl "localhost:9200/post_search/_search?q=汐语测试" 直接看到文档

【亲眼确认】90 秒内搜索页搜"汐语测试"→ 你的帖子出现，关键词带 高亮。实测基线：发帖→可搜全程 ~1.9 秒。

【翻车对照】搜索页显示"搜索服务暂不可用" → ES 没起（软依赖降级，起 ES 即恢复）；90 秒还没进索引 → 按四站顺序查哪站断：①没日志=canal 挂 ②topic 没消息=canal→MQ 断 ③控制台无消费=consumer 挂 ④docs 没涨=回源写 ES 失败。
