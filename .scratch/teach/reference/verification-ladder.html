验证阶梯：8 级亲眼确认系统 work

从"最有实感"到"最严谨"——每一级都是一种亲手验证系统的手段。这张表会陪你走完整门课。

这张表怎么用 需要启动项目或验证某个功能时，按需查对应级别的操作步骤。这里的 L0→L7 是验证手段的索引，不是必须依次完成的课程。
进度说明（2026-10-20） 这份阶梯仅作为启动和测试验证的操作参考，不再代表主学习路线，也不要求逐级打卡。主线改为按用户功能学习，当前状态见同目录 ../PROGRESS.md。

阶梯总览

级别验证手段你能亲眼看到什么工具状态
L0 点亮全栈 14 个容器逐个从 starting 变 healthy docker compose 第 1 课
L1 前端点点点 浏览器里登录→发帖→搜索，页面真的响应你 浏览器 :3000 第 2 课
L2 API 层直调 Swagger UI 里点一下按钮，看到 HTTP 请求/响应原文 Swagger :8090 / curl 第 3 课
L3 中间件控制台 看见平时看不见的：服务注册、消息流动、ES 索引、对象文件 Nacos/RocketMQ/Kibana/MinIO 第 4 课
L4 冒烟脚本 一条命令自动跑完整链路，打印 PASS/FAIL node scripts/*.mjs 第 5 课
L5 跑单个测试类 看某一段逻辑的红/绿，秒级反馈 mvnw test -Dtest= 第 6 课

万能排障三件套

# 1. 看某个服务为什么起不来（最常用）
docker compose logs -f backend

# 2. 看所有服务健康状态
docker compose ps

# 3. 数据脏了想彻底重置（会删数据库和图片！确认后再用）
docker compose down -v
